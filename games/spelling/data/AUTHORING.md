# 英文單字拼圖：詞庫撰寫與審閱規範

本規範同時給撰寫 agent 與審閱 agent 使用。規格見 `games/spelling/spec.md` 的「詞庫」一節。

## 檔案

- 單字清單（不可修改）：`data/list.json`。由 `scripts/normalize-list.mjs` 從大考中心「高中英文參考詞彙表」（`data/ceec/`）整理而成。
- 撰寫批次（不可修改）：`data/batches/level-<n>-<批次>.json`，每筆含 `id`、`en`、`pos`、`level`。
- 撰寫初稿：`data/draft/level-<n>-<批次>.json`（只有撰寫 agent 會寫這裡）。
- 審閱後定稿：`data/words/level-<n>-<批次>.json`（只有審閱 agent 會寫這裡）。
- 審閱紀錄：`data/reviews/level-<n>-<批次>.md`。
- 驗證：`node scripts/validate-words.mjs <檔案>`，必須沒有任何錯誤。

## 每個單字的欄位（JSON 物件）

```json
{
  "id": "library",
  "en": "library",
  "pos": "n.",
  "level": 1,
  "zh": "圖書館",
  "example": "I borrowed three books from the school library.",
  "form": "",
  "exampleZh": "我從學校圖書館借了三本書。"
}
```

| 欄位 | 規則 |
| --- | --- |
| `id`、`en`、`pos`、`level` | **照抄批次檔，一個字都不能改**（包含順序；批次中的每個單字都要寫，不可增刪）。 |
| `zh` | **台灣用語、繁體中文**，12 字以內。依 `pos` 取最常用的 1～2 個意思，以「、」分隔（例如 *act* n./v. →「行為、行動」）。不要寫詞性、括號、英文或逗號。多個詞性時以最常用的詞性為主。 |
| `example` | 自然的英文例句，**15 個英文單字以內**，必須包含該單字。**盡量只用同 Level 或更低 Level 的常見單字**，讓學生看得懂。題材以校園、家庭、旅行與日常生活為主。 |
| `form` | 例句中該單字以**變化形**出現時，填例句中實際出現的字（例如 *buy* 的例句用 *bought* 填 `"bought"`，名詞複數 *apples* 填 `"apples"`，比較級 *bigger* 填 `"bigger"`）；例句中是原形時填空字串 `""`。 |
| `exampleZh` | 例句的通順中文翻譯（台灣用語、繁體中文）。 |

### 中文意思的注意事項

- 台灣用語：*subway*「地鐵、捷運」、*potato*「馬鈴薯」、*software*「軟體」、*video*「影片、錄影」、*quality*「品質」、*program*「節目、程式」。
- 中文意思是玩家拼字的唯一線索，要**能讓人想到這個英文字**。意思相近的字（例如 *big*／*large*、*begin*／*start*）不需要刻意區分，遊戲會接受中文與詞性都相同的字。
- 不得出現簡體字（例如「软件」「这」）。

### 例句也是出題的線索

- 出題時，例句會顯示在中文意思下方，**該單字挖空成底線**（例如「I borrowed three books from the school ＿＿＿.」），幫助玩家想到要拼哪個字。功能詞（*of*、*to*、*be*）與多義字（*fall* 秋天／掉落）特別靠例句區分。
- 所以例句要讓人從上下文猜得出這個字，不要太空泛（例如「This is a ___.」）；同一句中該單字只出現一次。
- 例句取用的意思要與 `zh` 的第一個意思一致。

### 官方清單中的敏感字

- 清單中有少數涉及宗教、政治、死亡、暴力或性別、性取向的字（例如 *god*、*socialism*、*murder*、*lesbian*）。這些字照樣收錄，例句寫成中性、知識性的情境（例如歷史課、新聞、博物館、生物課），不表達立場、不描寫細節。

### 禁止事項

- 內容須**原創撰寫**，不得複製字典、教材或出版品的解釋與例句。
- 避免政治、宗教、暴力、性與歧視性題材；例句中不出現真實人物或品牌。

## 撰寫 agent 的工作

- 讀指派的批次檔，為每個單字寫 `zh`、`example`、`form`、`exampleZh`，輸出到 `data/draft/<同檔名>`（JSON 陣列，UTF-8，每筆一行或縮排 2 格都可以）。
- 單字數多時可分段寫入，但最終檔案必須是一個完整的 JSON 陣列，筆數與順序和批次檔相同。
- 寫完執行 `node scripts/validate-words.mjs data/draft/<檔名>`，修到沒有錯誤。

## 審閱 agent 的工作

- 審閱 agent **不是撰寫者**，只依本規範判斷，對每一個單字逐筆檢查：
  1. 中文意思正確、為台灣用語與繁體中文、是該詞性最常用的意思、能讓人想到這個英文字。
  2. 例句文法正確、自然、確實用到這個單字的這個意思（與 `zh` 的第一個意思一致）；挖空後能從上下文猜出這個字；該單字只出現一次；用字難度適合該 Level；`form` 與例句一致。
  3. 例句翻譯正確通順。
  4. 符合題材限制；敏感字的例句中性、知識性。
  5. `zh` 與 `pos` 一致：`pos` 有多個詞性時，`zh` 取最常用詞性的意思（例如 *chair* n. 應為「椅子」）。
- 結果：
  - **通過**：原樣保留。
  - **修正**：直接修正（中文用詞、例句、翻譯、`form`），並在紀錄中寫下原本內容、修改內容與原因。
- 審閱完成後：
  - 把結果寫到 `data/words/<同檔名>`，每個單字加上 `"reviewed": true`；筆數、順序與批次檔相同。
  - 執行 `node scripts/validate-words.mjs data/words/<檔名>`，必須沒有錯誤。
  - 寫審閱紀錄 `data/reviews/<檔名去掉 .json>.md`：檢查數量、通過數、修正數，並逐一列出修正的單字、原本內容、修改內容與原因。
