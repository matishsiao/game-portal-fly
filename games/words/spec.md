# 英文單字連線網頁版規格

共通要求（產品原則、大廳整合介面、遊戲流程、交通工具上的操作、暫停與計時、統計、本機儲存、PWA 與離線、相容性、部署與共用驗收）依 [`games/spec.md`](../spec.md)。本文件只寫英文單字連線特有的內容，以及對共用規格的補充與例外。

## 產品範圍

- 目錄名稱 `words`（部署網址 `/words/`，localStorage 前綴 `words.`，快取前綴 `words-`），大廳顯示名稱「英文單字連線」。
- 玩法：配對連連看。左欄是英文單字，右欄是打亂順序的中文意思；玩家點一個英文、再點對應的中文，兩者連成一條線。一盤全部配對完成後進入下一盤。
- 單字**依分類**出題：玩家先選分類（例如「機場與飛行」「餐廳點餐」），再選難度，出題只從該分類取字；也可以選「綜合」從所有分類出題。
- 詞庫為**生活單字，最多 5,000 個**，以出國旅行與日常生活實用為優先。
- **核心價值：在旅途中把零碎時間變成背單字的時間。** 每盤完成後顯示單字卡（英文、詞性、中文、生活例句與翻譯），並以「單字本」記錄學過與需要複習的單字。
- 不在本版範圍：拼字輸入、聽寫、片語與句型練習、音標顯示、自訂單字清單、與他人比賽。

## 共用規格的例外

- **發音（例外：共用規格「不播放任何聲音」）**：學英文需要聽發音，因此提供「發音」按鈕。
  - 只在玩家**主動點按**時播放，遊戲過程中不自動發出任何聲音。
  - 使用裝置內建的語音合成（Web Speech API，英文語音），不下載任何音檔；裝置沒有可用的英文語音時隱藏發音按鈕，不影響遊玩。
  - 離線時能否發音取決於裝置是否內建英文語音，須在說明中告知。
  - 設定中可關閉發音按鈕。
  - 自動挑選音質最好的英文語音：排除趣味／特效語音（如 macOS 的 Albert、Zarvox），優先「高品質／加強版／Natural」與常見的高品質語音（Samantha、Google US English、Microsoft Aria 等）；離線時不使用需要網路的語音。
  - 設定中可自選語音（選擇後試聽一次）與語速（正常、慢速）。
  - 行動裝置相容：遊戲卡片本身是按鈕，卡片內的發音圖示不可再用按鈕（手機點按會被卡片接走），由卡片的點按事件判斷是否點在發音圖示上；iOS 一開始可能回報空的語音清單且不觸發 `voiceschanged`，此時仍顯示發音按鈕並交給系統預設的英文語音，同時每 0.5 秒重查清單（最多 10 秒）；指定語音播放失敗時改用預設英文語音重試。
  - iPhone 靜音模式：網頁無法讀取 iOS 的靜音開關。發音前若支援 `navigator.audioSession`（iOS 16.4 以上）就設為 `playback`，嘗試不受靜音影響；並在 iPhone／iPad 上每次開啟後第一次發音時，於畫面下方短暫提示「沒聽到聲音？請關閉 iPhone 的靜音模式並調高音量」（不阻擋操作、約 4.5 秒後消失）。
- **不採用共用規格的「邏輯技巧分級」**：本遊戲的難度取決於單字的常見度與題型，而非推理技巧，因此由下方「難度」一節的條件決定；共用規格中「答案唯一」的精神仍然適用（同一盤不得有兩個可互換的答案）。

## 詞庫

### 分類

- 約 30 個分類，每個分類 80～250 個單字；一個單字可屬於多個分類（例如 *ticket* 同時屬於「交通運輸」與「娛樂休閒」）。
- 分類清單（可依內容微調，但上架後分類 id 不得更改）：

  | 群組 | 分類 |
  | --- | --- |
  | 旅行 | 機場與飛行、旅館住宿、交通運輸、問路與方向、觀光景點、緊急狀況 |
  | 吃喝 | 食物、飲料、餐廳點餐、水果與蔬菜、廚房與烹飪 |
  | 購物 | 購物與商店、金錢與付款、衣物與配件、顏色與形狀 |
  | 生活 | 家居用品、家庭與人物、身體部位、醫療與藥局、天氣與季節、時間與日期、數字與數量 |
  | 社會 | 職業與工作、學校與學習、城市與地點、科技與網路、運動與休閒、娛樂與媒體 |
  | 語言 | 常用動詞、常用形容詞、情緒與個性、問候與禮貌用語、動物、大自然 |

### 內容

- 詞庫原始檔為 `data/words/<分類 id>.json`（審閱後定稿），以 `npm run words` 合併為 `src/js/words-data.js` 隨遊戲離線快取；同一個 id 出現在多個分類時合併分類。每個單字包含：

  | 欄位 | 說明 |
  | --- | --- |
  | `id` | 穩定的識別碼，一經發布不得更改（單字本以此記錄進度）。規則：英文轉小寫並以連字號連接；名詞與固定詞組不加後綴，其他詞性加 `-v`、`-adj`、`-adv` 等後綴；同一英文與詞性但意思不同時加 `-2`（例如 `park` 公園、`park-v` 停車）。由 `scripts/normalize-ids.mjs` 統一檢查 |
  | `en` | 英文單字或固定詞組（如 *boarding pass*），以美式拼寫為準 |
  | `pos` | 詞性：n.、v.、adj.、adv.、phr. 等 |
  | `zh` | 中文意思：台灣用語與繁體中文，簡短（12 字以內），一個單字取最常用的 1～2 個意思 |
  | `categories` | 所屬分類 id（至少一個） |
  | `level` | 常見度：1 基礎（國中程度、最常用）、2 一般、3 進階 |
  | `syn` | 選填：同義群組 id，意思相近而會混淆的單字（如 *big* 與 *large*）使用相同的 id。群組以分類為範圍；建置時輸出為「分類:群組」陣列，同一個字出現在多個分類時保留每個分類的群組 |
  | `example` | 生活例句（英文，15 個單字以內，須包含該單字） |
| `form` | 例句中該單字以變化形出現時的實際字形（例如 *buy* 的例句用 *bought*）；原形時為空字串。單字卡以此將例句中的單字標為粗體 |
  | `exampleZh` | 例句的中文翻譯 |
  | `reviewed` | 是否已通過審閱 agent 的檢查；只有 `true` 的單字會出現在遊戲中 |

- 數量：上限 5,000 個；**首次上架至少 2,000 個**（每個分類至少 50 個），之後分批補充到 5,000。常見度大致為基礎 40%、一般 40%、進階 20%。
- 內容須**原創撰寫**：單字清單可依常用字頻與生活情境自行整理；中文意思與例句須自行撰寫，不得複製字典、教材或出版品的內容。
- 例句以出國旅行與日常生活情境為主，避免政治、宗教、暴力與歧視性題材。
- 中文意思須符合台灣用法（例如 *subway*：「地鐵、捷運」，*parking lot*：「停車場」）。

### 品質把關

- **撰寫與審閱分開**：單字初稿由撰寫 agent 產生，再交由**另一個獨立的審閱 agent** 逐筆檢查，通過後才可標記 `reviewed`。審閱 agent 不參與撰寫，也不沿用撰寫 agent 的對話內容，只依本節的標準判斷。
- 審閱 agent 對每個單字檢查：
  - 中文意思是否正確、是否為台灣用語與繁體中文、是否取了最常用的意思。
  - 詞性是否正確；分類是否合理；常見度是否合理。
  - 例句文法是否正確、是否自然、是否確實用到該單字的這個意思；例句翻譯是否正確。
  - 同義群組是否標記完整（同分類中意思會混淆的單字是否放在同一群組）。
  - 內容是否符合題材限制。
- 審閱結果分為「通過」「修正後通過」「退回」：可以直接修正的小錯由審閱 agent 修正並在審閱紀錄中註明；需要重寫的退回撰寫 agent，重寫後再交審閱。
- 每批（例如一個分類）完成審閱後，產生審閱紀錄 `data/reviews/<分類>.md`：檢查數量、通過數、修正與退回的單字及原因。
- 使用者可隨時抽查；抽查發現的錯誤回饋給審閱標準，並重新審閱同類問題。
- 自動化驗證（`npm test`）：
  - `id`、`en` 不重複；`en` 只含英文字母、空格、連字號與撇號。
  - `zh` 不為空且不超過 12 字；同一分類中 `zh` 完全相同的單字必須屬於同一個 `syn` 群組。
  - `example` 包含 `en`（可為變化形，例如 *buy* 對 *bought*，以詞形對照表檢查）；`exampleZh` 不為空。
  - 每個 `categories` 都存在於分類清單；每個分類達到最低數量。
  - 總數不超過 5,000。

## 難度

| 難度（代碼） | 一盤配對數 | 一局盤數 | 單字常見度 | 題型 | 每局提示額度 |
| --- | ---: | ---: | --- | --- | ---: |
| 簡單（`easy`） | 4 組 | 5 盤 | 1 | 英文 → 中文 | 5 次 |
| 中等（`medium`） | 5 組 | 5 盤 | 1～2 | 英文 → 中文 | 4 次 |
| 困難（`hard`） | 6 組 | 5 盤 | 2～3 | 英文 → 中文，同盤單字取自同一分類且**詞性相同**（數量足夠時），較難從詞性猜答案 | 3 次 |
| 專家（`expert`） | 6 組 | 5 盤 | 2～3 為主 | **中文 → 英文**（左欄中文、右欄英文），同盤詞性相同且**開頭字母相同**的單字優先（拼字相近，例如 sushi／salmon／sausage） | 2 次 |

- 某分類該難度的可用單字不足一局所需時，自動從相鄰常見度補足，並在開始前提示。
- 同一盤內：
  - 不得出現同一個 `syn` 群組的兩個單字，也不得出現 `zh` 相同的兩個單字（確保答案唯一）。
  - 不得出現同一個單字的兩個詞性。
- 選字順序：優先出玩家**尚未學過**的單字，其次為「待複習」與較久沒出現的單字；同一局不重複出題。

## 畫面與操作

- 遊戲畫面上方顯示分類、難度、盤數進度（例如「3 / 5」）、耗時與錯誤次數。
- 中央兩欄卡片：左欄（題目）與右欄（答案）各 4～6 張，卡片高度至少 48 CSS px，文字不截斷（過長時縮小字級或換行）。
- **配對方式（點選，不使用拖曳）**：先點左欄或右欄任一張卡片選取，再點另一欄的卡片配對；也可以先點右欄。拖曳在晃動的交通工具上容易失手，因此不採用。
- 配對正確：兩張卡片間畫出一條線（SVG），卡片變為完成色並鎖定，線保留到該盤結束。
- 配對錯誤：兩張卡片短暫標紅並加 ✕，累計一次錯誤次數，之後恢復未選取狀態；錯誤的配對不保留連線。
- 點選已選取的卡片可取消選取；點同一欄的另一張卡片則改選那張。
- 英文卡片上有發音按鈕（若可用），點按播放該單字的發音，不影響配對。
- 提示：自動為一組尚未配對的卡片畫出正確連線並鎖定，扣 1 次。
- 一盤全部配對完成後，以短暫、單次的效果標示完成，接著顯示本盤的單字卡；按「下一盤」繼續。
- 復原：不提供（配對沒有連鎖效果，錯誤配對不保留，因此不需要）。
- 桌面鍵盤：方向鍵在卡片間移動、Enter 或空白鍵選取；數字鍵 1～6 選左欄第 N 張、Q／W／E／R／T／Y 選右欄第 N 張；H 提示、P 或 Esc 暫停。
- 暫停時遮住所有卡片與單字卡。

## 單字卡與單字本

### 單字卡

- 內容：英文（大字）與發音按鈕、詞性、中文意思、例句與例句翻譯；例句中的該單字以粗體標示。
- 出現時機：每盤完成後列出該盤的單字；完成畫面可再次查看本局所有單字。
- 單字卡文字可選取複製。

### 完成畫面

- 依共用規格顯示難度、耗時、錯誤次數、已用提示次數與最佳紀錄。
- 另外顯示分類、本局練習的單字數，並列出本局答錯過的單字（可點開單字卡）。

### 單字本

- 從首頁進入，顯示「已學會 N / 詞庫總數」，以及每個分類的學習進度（例如「機場與飛行 42 / 120」）。
- 「已學會」：至少一次在沒有答錯、沒有使用提示的情況下完成配對的單字。
- 「待複習」分頁：答錯或使用提示的單字；之後一次答對即移出。
- 可依分類篩選、以英文或中文搜尋；點選單字顯示單字卡。

## 首頁

- 分類以卡片列表呈現，依群組分段；每張卡片顯示分類名稱、圖示、學習進度條（已學會 / 總數）。
- 點選分類後選擇難度並開始；另有「綜合」與「待複習」兩種快速開始（「待複習」只出待複習的單字，數量不足時以同常見度的單字補足）。
- 依共用規格提供繼續遊戲、統計、玩法說明、設定（發音開關、語音、語速）與「‹ 所有遊戲」。

## 本機儲存

依共用規格，另外：

| 鍵 | 內容 |
| --- | --- |
| `words.save` | 目前一局：分類、難度、每盤的單字 id 與排列順序、已完成的配對、目前盤數、錯誤次數、已用提示、耗時；欄位符合大廳讀取格式 |
| `words.stats` | 共用格式（`easy`、`medium`、`hard`、`expert`） |
| `words.book` | 單字本：以單字 `id` 為鍵，記錄出現次數、答對次數、是否已學會、是否待複習、最後出現時間 |
| `words.recent`、`words.settings` | 最近出現的單字（避免短期重複）、設定（發音開關、語音、語速） |

- 存檔只記錄單字 `id`，讀取時從詞庫取回內容；詞庫更新後不存在的 `id` 依「資料損毀」流程處理該局，單字本中不存在的 `id` 直接略過。

## 外觀

- 遊戲主色：**天藍到湖水綠**的清爽漸層（`--brand-1: #3aa7e0`、`--brand-2: #22b39a`），與其他遊戲區隔；首頁橫幅點綴淡色的英文字母與小飛機圖案。
- 左右卡片使用不同的淡底色區分欄位；選取中的卡片加粗外框；完成的配對使用柔和的綠色與連線。
- 分類圖示使用系統內建的 emoji（例如 ✈️ 🍽️ 💳），不需額外圖檔、離線也能顯示。
- 其餘依共用規格的豐富色調要求；上架時大廳卡片使用相同的漸層。

## 驗收條件

除共用驗收條件外：

1. 詞庫驗證測試全部通過；首次上架至少 2,000 個已審閱單字、每個分類至少 50 個，總數不超過 5,000；每個分類都有審閱 agent 的審閱紀錄；另由審閱 agent 以外的檢查隨機抽查 100 個單字的中文意思、詞性與例句，錯誤少於 1 個。
2. 每個分類、每個難度各產生 50 局：同一盤內沒有同義群組重複或 `zh` 相同的單字、沒有同一單字的兩個詞性；同一局不重複出題；配對數與題型符合難度設定。
3. 配對：先點左欄或右欄皆可；正確時畫線並鎖定、錯誤時標紅加 ✕ 並計錯誤；取消選取與改選正確。
4. 提示畫出正確連線並扣次數；用完後停用並說明。
5. 每盤完成後顯示單字卡，例句中的單字以粗體標示；完成畫面列出答錯過的單字。
6. 單字本：「已學會」與「待複習」的判定與移出規則正確，各分類進度正確；搜尋與篩選正確。
7. 發音：只在點按時播放；裝置沒有英文語音時隱藏按鈕；關閉設定後不顯示按鈕；其他時候不發出任何聲音。
8. 重新整理或在背景被系統結束後再開啟，分類、難度、盤數、已完成的配對、錯誤次數、提示餘額與耗時都與最後一次操作一致。
9. 手機直向 375 CSS px 寬可單手完成所有操作，6 組配對的兩欄卡片完整顯示且不截斷文字。
10. 大廳顯示「英文單字連線」卡片、離線可玩、版本號、繼續遊戲與戰績（依「上架到大廳」驗證）。

## 開發順序

1. **詞庫**：確定分類清單與資料格式、驗證測試；由撰寫 agent 分批產生初稿、審閱 agent 逐筆審閱，先完成 2,000 個（每類至少 50 個）；全部審閱後以 `scripts/unify-meanings.mjs` 統一跨分類同一意思的中文寫法（修改附加到審閱紀錄），再執行 `scripts/normalize-ids.mjs` 統一 id。
2. **出題器**：依分類與難度選字、同盤避免同義與重複、優先未學與待複習；批次驗收腳本（`npm run check:puzzles`）。
3. **遊戲畫面**：兩欄配對與連線、錯誤與提示、單字卡、完成畫面。
4. **單字本與首頁分類**。
5. **發音**（Web Speech API 與設定開關）。
6. **外觀與離線**：豐富色調、PWA、離線與更新流程。
7. **上架到大廳**：依共用規格「上架到大廳」完成並驗收。
8. **持續擴充**：分批補充單字到 5,000 個，每批都須經審閱 agent 審閱並通過驗證。
