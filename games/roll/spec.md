# 滾滾解謎（物理邏輯解謎）網頁版規格

共通要求（產品原則、大廳整合介面、遊戲流程、交通工具上的操作、暫停與計時、統計、本機儲存、PWA 與離線、相容性、部署與共用驗收）依 [`games/spec.md`](../spec.md)。本文件只寫滾滾解謎特有的內容，以及對共用規格的補充與例外。

## 產品範圍

- 目錄名稱 `roll`（部署網址 `/roll/`，localStorage 前綴 `roll.`，快取前綴 `roll-`），大廳顯示名稱「滾滾解謎」（暫定）。
- 玩法：從側面看的迷宮中，玩家控制小球角色「滾滾」移動，利用不同物體的物理特性開路，抵達終點。例如：
  - 推動箱子清除障礙，或把箱子推到坑裡當踏板。
  - 利用重力讓物體掉落，壓碎下方的易碎磚。
  - 利用浮力讓木箱浮在水面上，當作過水的踏板。
  - 利用摩擦力很小的冰塊，一推就滑到底；利用彈簧把角色或物體彈到高處。
- **核心價值：玩的同時理解重力、浮力、摩擦力、彈力等物理概念。** 每個新物件第一次出現時，以一張「物理小知識」卡說明原理與生活例子。
- 產品特性：
  - **回合制、格子化的物理**：每次操作後依固定規則計算結果，不使用即時物理引擎；同樣的操作永遠得到同樣的結果，可以用程式驗證每一關都能過關。
  - 關卡依章節循序解鎖，每章介紹一種物理概念，難度逐步提高。
  - 隨時可以復原與重新開始本關，不會卡死。
- **原創要求**：本遊戲的玩法概念參考市面上的物理解謎遊戲（例如 Avokiddo 的 Thinkrolls），但**名稱、角色、美術、文字與所有關卡都必須原創**；不得使用 Thinkrolls 的名稱、角色、圖像、音效或照抄其關卡配置。
- 不在本版範圍：即時動作（跳躍、計時閃避）、關卡編輯器開放給玩家、多角色切換、音效、每日關卡、關卡分享。

## 共用規格的例外

- **不使用隨機出題**（共用規格「出題」一節不適用）：本遊戲的價值在於循序漸進地介紹物理概念，關卡須依教學順序精心設計，因此採固定關卡；以自動化解題器驗證每一關（見「關卡驗證」）。共用規格中「必須能解」「不需猜測或試錯」「不需要網路」的精神仍然適用。
- **不計錯誤次數**：解謎過程沒有「填錯」的概念，走錯路只會卡住，以復原或重新開始處理。完成畫面以「步數」取代「錯誤次數」。
- **一局等於一關**：共用規格的「一局」在本遊戲指「一個關卡從開始到過關」；「同時只保存一局」指目前進行中的關卡。章節進度（已過關卡、星數）另外永久保存，不受開始新局影響。
- **難度代碼對應章節**：四個章節依序對應 `easy`、`medium`、`hard`、`expert`，供大廳顯示進度與戰績（見「關卡與章節」）。

## 規則

### 盤面

- 側視格子盤面，寬 7～10 格、高 7～12 格；每格最多一個實體物件。
- 地形：
  | 格子 | 說明 |
  | --- | --- |
  | 牆 | 不可通過、不受重力影響 |
  | 空氣 | 可通過 |
  | 梯子 | 角色可在梯子上上下移動，梯子上不會掉落；物體無法停在梯子上（會穿過掉落） |
  | 水 | 角色不能進入；物體依浮沉規則處理 |
  | 終點 | 角色抵達即過關 |

### 物件

| 物件 | 物理概念 | 行為 |
| --- | --- | --- |
| 滾滾（角色） | 重力 | 左右移動一格；下方沒有支撐時往下掉，直到落在支撐物上；在梯子上可上下移動 |
| 木箱 | 重力、浮力 | 可被推動；會掉落；落入水中時**浮在水面**（停在最上層的水格），可當踏板 |
| 石塊 | 重力、密度 | 可被推動；會掉落；落入水中**沉到水底**；從 2 格以上的高度掉落時壓碎下方的易碎磚 |
| 冰塊 | 摩擦力 | 被推動後**一直滑行**，直到前方有阻擋才停下；會掉落；在水中浮起 |
| 易碎磚 | 衝擊 | 支撐物件；被從 2 格以上高度掉落的石塊撞擊時碎裂消失 |
| 彈簧 | 彈力 | 固定不動；角色或物體從上方落到彈簧上時，被往上彈 3 格（遇到阻擋則停在阻擋下方） |
| 氣球 | 浮力（空氣） | 會**往上飄**直到被阻擋；可被推動；角色可站在氣球上被帶著往上 |

- 推動：角色往某方向移動、且該格是可推動物件時，若物件前方是空氣（或物件可滑入的格子），物件與角色一起前進一格；一次只能推動一個物件，前方被擋住則不能移動。
- 支撐：牆、梯子頂端、物件與浮在水面的物件都可以支撐其上的角色與物件。
- 每次操作後依固定順序結算，直到盤面靜止：
  1. 角色移動與推動。
  2. 冰塊滑行。
  3. 重力與浮力：由下往上逐格處理掉落、上飄、浮起與沉底；落在彈簧上的角色或物體彈起。
  4. 衝擊：判定易碎磚是否碎裂，碎裂後回到步驟 3。
  5. 角色位於終點即過關。
- 規則的精確定義（同時發生時的先後順序、邊界情況）以規則程式與單元測試為準，並在 `README.md` 以圖例說明；規則變更須同步重新驗證所有關卡。

## 關卡與章節

| 章節（代碼） | 主題 | 新物件 | 關卡數 |
| --- | --- | --- | ---: |
| 第 1 章（`easy`） | 重力與推箱子 | 牆、梯子、木箱、石塊 | 20 |
| 第 2 章（`medium`） | 浮力與水 | 水（木箱浮、石塊沉）、氣球 | 20 |
| 第 3 章（`hard`） | 摩擦力與衝擊 | 冰塊、易碎磚 | 20 |
| 第 4 章（`expert`） | 彈力與綜合應用 | 彈簧，以及前面所有物件的組合 | 20 |

- 本版共 80 關。關卡依序解鎖：通過一關即解鎖下一關；通過一章的第 15 關即解鎖下一章（不必全部過關）。
- 每章前幾關各以一個新物件為主角，讓玩家先單獨認識它，再與舊物件組合。
- 星等：過關得 1 星；步數不超過「最少步數 × 1.5」（無條件進位）得 2 星；步數等於最少步數且未使用提示得 3 星。只保留每關最佳紀錄。
- 關卡檔：`src/levels/<章節>-<編號>.txt`，以文字字元表示格子與物件（例如 `#` 牆、`H` 梯子、`~` 水、`B` 木箱、`S` 石塊、`I` 冰塊、`x` 易碎磚、`^` 彈簧、`o` 氣球、`@` 滾滾、`*` 終點），另附關卡名稱與該關的教學提示。建置時合併為 `src/levels.json` 隨遊戲離線快取。

### 關卡驗證（自動化）

- 以廣度優先搜尋的解題器驗證每一關：
  - 必須可以過關，記錄最少步數與一組最佳解。
  - 盤面合法：只有一個角色、至少一個終點、邊界由牆圍起。
  - 解題器的搜尋上限（例如 200 萬個狀態）內找不到解即判定失敗。
- 章節內的難度須大致遞增：以最少步數與搜尋的狀態數作為參考指標，批次驗收腳本列出每關數值，供設計者調整順序。
- `npm run check:levels` 驗證全部關卡；任何一關失敗即視為建置失敗。
- 關卡設計可以用輔助腳本隨機產生候選盤面、再以解題器篩選，但上架的關卡須經人工挑選與調整，並確認符合該章的教學主題。

## 畫面與操作

- 遊戲畫面上方為章節與關卡名稱、步數、耗時；中央為盤面；下方為操作區。
- 盤面以簡單的向量圖形繪製（SVG 或 Canvas），物件外觀可一眼辨識，且除了顏色還有形狀或圖示差異（例如冰塊有反光線條、石塊有裂紋）。盤面格子在 375 CSS px 寬的直向畫面上至少 34 × 34 CSS px。
- 操作：
  - **方向鍵按鈕**：畫面下方的左、右、上、下四個大按鈕（至少 56 × 56 CSS px），一次移動一步。上、下只在梯子上有效。
  - **點選目的地**：點選盤面上的一格，角色沿不需要推動物件的最短路徑走過去；途中需要推動物件或無法到達時不移動，並以短訊息說明。
  - 不使用滑動手勢，避免搭車時誤觸。
- 動畫：每一步的移動、掉落、滑行以短暫動畫呈現（每格約 80～120 毫秒），動畫期間的新操作排入佇列；系統設定「減少動態效果」時直接顯示結果。不使用持續播放的動畫。
- 無法執行的操作（推不動、上下時不在梯子上）以角色輕微晃動與短訊息說明，不計步數。
- 復原：可無限次逐步復原（含物件的連鎖結果）；「重新開始本關」須確認。
- 提示：每關 3 次，每次以箭頭示範最佳解的下 3 步（從目前狀態重新計算最佳解）；目前狀態已無法過關時，提示改為建議「復原」或「重新開始」，不扣次數。使用提示的關卡最高 2 星。
- 桌面鍵盤：方向鍵移動、Ctrl／⌘＋Z 或 U 復原、R 重新開始本關（須確認）、H 提示、P 或 Esc 暫停；N 鍵忽略。
- 暫停時遮住盤面。

## 物理小知識

- 每個物件第一次出現的關卡開始前，顯示一張「物理小知識」卡：物件名稱、一句話說明它在遊戲中的行為、背後的物理概念與一個生活例子（例如冰塊：「冰面很滑，摩擦力很小，所以推一下就會一直滑；就像在溜冰場上滑行一樣。」）。
- 所有看過的小知識收錄在首頁的「物理圖鑑」，可隨時重看。
- 文字以國小高年級能理解的程度撰寫，內容須正確（例如浮力與密度的關係）；全部為原創文字。

## 遊戲流程

- 首頁：章節列表（顯示各章已得星數與解鎖狀態）、繼續遊戲、物理圖鑑、統計、玩法說明，以及「‹ 所有遊戲」。
- 點選章節進入關卡列表（格狀排列，顯示關卡編號、星數與鎖定狀態），點選已解鎖的關卡開始。
- 過關畫面：步數、最少步數、耗時、星數、是否使用提示，並提供「下一關」「重玩」「回關卡列表」。
- 從關卡列表開始其他關卡時，若目前有進行中且已操作過的關卡，須先確認（目前那關的進度會被捨棄；已得到的星數不受影響）。

## 統計

依共用規格的格式記錄於 `roll.stats`，以章節代碼為鍵：

- `started`：開始過的關卡次數；`completed`：過關次數（含重玩）；`bestMs`：該章任一關的最短過關時間；`totalMs`：過關耗時總和；`noHint`：未使用提示過關的次數。
- 首頁的統計另外顯示每章的已過關卡數、總星數與三星關卡數（由 `roll.progress` 計算）。

## 本機儲存

依共用規格，另外：

| 鍵 | 內容 |
| --- | --- |
| `roll.save` | 目前進行中的關卡：關卡 id、目前盤面狀態、步數、已用提示、耗時，以及大廳讀取用的 `difficulty`（章節代碼）、`elapsedMs`、`completed` |
| `roll.progress` | 永久進度：以關卡 id 為鍵記錄是否過關、最佳星數、最佳步數；已解鎖的章節與關卡由此計算 |
| `roll.book` | 已看過的物理小知識 |
| `roll.stats`、`roll.settings` | 依共用規格 |

- 復原紀錄不需在重新整理後保留；重新整理後從存檔的盤面狀態繼續。
- 關卡 id（例如 `1-07`）一經發布不得更改；之後新增關卡只能加在章節末尾或新增章節，不得改變既有關卡的 id 與內容造成玩家進度錯亂（修正既有關卡時保留 id，並重新驗證）。

## 外觀

- 遊戲主色：**天空藍到草地綠**的漸層（`--brand-1: #4fb3e8` 天空藍、`--brand-2: #3f9a4a` 草地綠），營造戶外天空與綠地的感覺，與數獨、數學填字、成語填字區隔。
  - 首頁橫幅與遊戲頂部列由上往下從天空藍漸變到草地綠（上方為天空、下方為草地），背景點綴淡色的雲朵、箱子、氣球、彈簧剪影。
  - 盤面背景使用淡天空藍，地面與平台的牆面以草地綠為頂、土色為底，延續同一意象。
  - 深色模式改用夜空藍與深草綠，維持天空與綠地的對比。
- 各物件使用固定且容易區分的顏色與形狀；水面以半透明藍色表示。
- 其餘依共用規格的豐富色調要求；上架時大廳卡片使用相同的漸層。

## 驗收條件

除共用驗收條件外：

1. 規則單元測試涵蓋每種物件的行為與結算順序，包含：木箱浮在水面、石塊沉底、冰塊滑到阻擋為止、石塊從 2 格以上掉落壓碎易碎磚、彈簧彈起 3 格與遇阻擋提前停止、氣球上飄並帶起角色、一次只能推一個物件。
2. `npm run check:levels` 驗證全部 80 關可過關，並輸出每關最少步數與狀態數；每章前 5 關的最少步數不超過 30。
3. 同一關、同一串操作在任何裝置上得到完全相同的結果（以重播最佳解的測試驗證）。
4. 復原可回到任一步之前的完整盤面（含連鎖掉落、滑行、碎裂）；提示示範的步驟從目前狀態出發且確實能過關。
5. 星等計算正確；只保留最佳紀錄；過關後正確解鎖下一關與下一章。
6. 重新整理或在背景被系統結束後再開啟，進行中關卡的盤面、步數、提示與耗時都與最後一次操作一致；章節進度與星數不會遺失。
7. 每個新物件第一次出現時顯示物理小知識，並收錄到物理圖鑑。
8. 手機直向 375 CSS px 寬可單手完成所有操作，盤面不需縮放即可看清與點選；方向鍵按鈕在拇指可及範圍。
9. 名稱、角色、美術、文字與關卡皆為原創，未使用 Thinkrolls 的名稱、角色、圖像或關卡配置。
10. 大廳顯示「滾滾解謎」卡片、離線可玩、版本號、繼續遊戲與戰績（依「上架到大廳」驗證）。

## 開發順序

1. **規則引擎**：格子資料結構、物件行為與結算順序，完整單元測試。
2. **解題器與關卡格式**：文字關卡解析、廣度優先解題器、`npm run check:levels`。
3. **關卡設計**：先完成第 1 章 20 關驗證整體手感，再完成其餘章節；每章的物理小知識同步撰寫。
4. **遊戲畫面**：盤面繪製與動畫、方向鍵與點選目的地、復原與提示、過關畫面、章節與關卡列表。
5. **物理圖鑑與統計**。
6. **外觀與離線**：豐富色調、PWA、離線與更新流程。
7. **上架到大廳**：依共用規格「上架到大廳」完成並驗收。
