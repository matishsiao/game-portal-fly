# 社會探索：題庫撰寫與審閱規範

本規範給撰寫 agent 與兩種審閱 agent 使用。**先完整閱讀**：

- [`spec.md`](../spec.md) 的「內容原則：中立與正確」「題型與規則」「寫題原則」「題庫驗證」。
- [`terms.md`](terms.md)：用語對照表（「不使用」欄的寫法會被程式擋下）。
- [`topics.md`](topics.md)：每個難度的主題、涵蓋內容與題數。

## 檔案流程

| 階段 | 誰 | 讀 | 寫 |
| --- | --- | --- | --- |
| 1. 撰寫 | 撰寫 agent | 指派的難度與主題配額 | `data/draft/<難度>-<批次>.json` |
| 2. 事實查證 | 事實審閱 agent | `data/draft/` | `data/checked/<同檔名>`、`data/reviews/<檔名>-fact.md` |
| 3. 中立與適讀 | 中立審閱 agent | `data/checked/` | `data/bank/<同檔名>`（定稿）、`data/reviews/<檔名>-neutral.md` |

- 每個階段完成後執行 `node scripts/validate-bank.mjs <檔案>`，必須沒有錯誤。
- 遊戲只使用 `data/bank/`（`npm run bank` 合併為 `src/data/questions.json`、`src/data/cards.json`）。
- 審閱者有疑慮、需要人工決定的題目：從 `questions` 移到同一個檔案的 `held` 陣列（不會上架），並在審閱紀錄最後的「需要人工決定」列出原因。

## 檔案格式

```json
{
  "questions": [ { "id": "medium-001", "...": "..." } ],
  "cards": [ { "id": "medium-tw-periods", "...": "..." } ],
  "held": []
}
```

### 題目欄位

| 欄位 | 規則 |
| --- | --- |
| `id` | `<難度>-<三位數>`，依指派的編號範圍，不可重複 |
| `difficulty` | `easy`、`medium`、`hard`、`expert` |
| `subject` | `history`、`geography`、`civics` |
| `topic` | 主題代碼，必須屬於該科目（見 `topics.md`） |
| `grade` | 建議年級：`easy` 3～4、`medium` 5～6、`hard` 7～8、`expert` 9 |
| `type` | `choice`（選擇）、`order`（排序）、`sort`（分類） |
| `question` | 題目文字 |
| `options`、`answer` | 選擇題：4 個 `{ "text": "...", "hint": "..." }`，正確選項沒有 `hint`；`answer` 為正確選項索引（0～3），**正確選項位置要平均分散**（不要總是 0） |
| `material` | 選填，資料判讀：`{ "kind": "table", "head": [...], "rows": [[...]], "note": "虛構資料" }` 或 `{ "kind": "text", "body": "...", "note": "改寫" }`；表格 2～6 列、每格 12 字內；短文 150 字內；`note` 必填（「改寫」「虛構資料」或「資料年份：2020」） |
| `items`、`years` | 排序題：依**正確順序**排列的 3～5 個項目文字；歷史事件附 `years`（西元年，西元前用負數，與 items 一樣長且嚴格遞增）。項目文字不得含年份或「之後」「第二次」這類字 |
| `bins`、`cards` | 分類題：2～3 個類別；4～8 張卡片 `{ "text": "...", "bin": 0, "hint": "..." }`，`hint` 不得寫出類別名稱 |
| `keys` | 恰好 2 段解題重點，由淺到深，用提問或比較引導，不得寫出答案 |
| `explain` | 詳解：答案與原因（因果、脈絡或制度精神），讀完能學到東西 |
| `card` | 知識卡 `id` |
| `asOf` | 選填：題目依賴會變動的事實（人口、行政區數量、法定年齡）時，填資料年份，並在題目寫出「依 ○○ 年…」 |

### 知識卡欄位

`{ "id": "<難度>-<英文簡稱>", "subject": "history", "title": "名稱", "icon": "emoji", "body": "重點說明（100 字內）", "life": "與生活的關聯（1～2 句）", "mnemonic": "選填：記憶小撇步" }`

- 一張知識卡可以被多題連到；每張卡至少一題連到。
- id 以難度開頭（例如 `medium-tw-periods`），避免不同批次撞名。

## 撰寫 agent

- 依指派的主題配額寫題，題型比例：選擇題約 70%、排序題約 15%、分類題約 15%；`hard`、`expert` 的選擇題中至少 1/4 是資料判讀題（`material`）。
- 誘答選項取自學生常見的混淆，每個 `hint` 針對該選項的錯誤想法（可用「你是不是覺得…？」開頭），不得寫出正確答案。
- 不得出現**現任或近 10 年**的政治人物、政黨評價、選舉結果與民調；不得問「哪個比較好」這類價值判斷；有爭議的歷史評價不出題。
- 不使用真實的人名（課綱歷史人物除外）、店名、品牌與學校；公民情境用虛構的人物（小明、小華等）。
- 不寫「目前」「最新」「現任」「今年」；時效性事實要寫年份並填 `asOf`。
- 只寫你有把握的事實；不確定的內容不要出題。
- 完成後執行 `node scripts/validate-bank.mjs data/draft/<檔名>`，修到沒有錯誤。

## 事實審閱 agent

- 你不是撰寫者。**先不看答案**，自己作答每一題，再對照 `answer`／`items`／`bins`。
- 逐題查證題目、選項、提示、詳解與知識卡中的事實；以至少兩個可靠來源核對（政府機關、教育部或國家教育研究院、學術機構、博物館網站；不以論壇與內容農場為來源）。可以使用網路搜尋。
- 檢查：答案唯一、誘答確實錯、排序與分類只有一種合理答案、`years` 正確、簡化沒有簡化成錯的說法、年級用語合適。
- 直接修正錯誤；無法確認的事實改寫成可確認的內容，或把題目移到 `held`。
- 審閱紀錄 `data/reviews/<檔名>-fact.md`：檢查題數、修正數、移到 `held` 的題數；**每題列出查證來源（網站名稱與網址）**；修正的題目列出原本內容、修改內容與原因。

## 中立審閱 agent

- 你不是撰寫者，也不是事實審閱者。依 `spec.md`「內容原則」與 `terms.md` 逐題檢查：
  - 有沒有價值判斷、政治立場、爭議詮釋、評價性形容詞、刻板印象。
  - 用語是否依 `terms.md`；族群、宗教的描述是否尊重。
  - 戰爭、災難、犯罪有沒有不適合兒童的細節。
  - 用語與難度是否符合 `grade`；提示是否洩題；正確選項有沒有明顯較長或句型不同。
- 直接修正；有疑慮的題目移到 `held`。
- 審閱紀錄 `data/reviews/<檔名>-neutral.md`：檢查題數、修正數、移到 `held` 的題數；修正的題目列出原本內容、修改內容與原因；最後列「需要人工決定」。

## 共同規則

- 只寫自己階段的輸出檔與審閱紀錄，不修改其他檔案，不 git commit。
- 暫存檔放在自己專屬的暫存資料夾（其他 agent 同時在工作，不要用共用的檔名）。
- 內容一律原創，不得複製教科書、參考書、會考試題、百科或新聞的文字。
