# 離線小遊戲共用規格

本文件是 `games/` 下所有遊戲的共用規格，涵蓋產品原則、與遊戲大廳的整合介面、操作體驗、儲存、離線、部署與驗收。各遊戲目錄另有自己的規格（例如 `games/sudoku/spec.md`、`games/crossmath/cm_spec.md`），描述遊戲規則、盤面、難度、出題與該遊戲特有的操作。

## 文件關係

- 各遊戲規格只寫該遊戲特有的內容；共通要求以本文件為準，遊戲規格可直接引用（例如「暫停：依共用規格」）。
- 遊戲規格可以**加嚴或補充**本文件（例如更短的出題時間、額外的快捷鍵），不得放寬；確有需要放寬時，須在遊戲規格中明確寫出例外與理由。
- 「大廳整合介面」一節是大廳（`src/portal.js`、`scripts/assemble.mjs`）與遊戲之間的約定。修改這一節時，須同步修改大廳程式與所有遊戲。
- 本文件中的數值（例如觸控尺寸、逾時、最近題目數）是所有遊戲的預設值；遊戲規格未另行規定時即適用。

## 產品原則

- 可在手機及電腦瀏覽器遊玩的單機遊戲，介面使用繁體中文，以手機直向單手操作為主要情境。
- 主要使用情境：個人在國外旅行、搭機或搭車等沒有網路或網路不穩的環境下打發時間；遊戲常被登機、轉乘、來電等事件中斷，任何時刻離開都不得遺失進度。
- 首次開啟須連網下載資源；成功載入一次後，即使離線也能重新開啟、繼續遊戲及開始新局（含在裝置本機產生新題目）。
- 不需要帳號、後端、廣告、內購或遊玩時的網路連線；不收集任何分析或追蹤資料。
- 不播放任何聲音。
- 除非遊戲規格另行納入，以下不在範圍內：多存檔槽位、多語系、雲端同步、每日挑戰、排行榜、成就、音效。

## 專案結構與技術

- 每個遊戲是 `games/<目錄>/` 下的獨立專案，可單獨開發、測試與建置：

  ```
  games/<目錄>/
  ├── src/                原始碼，至少含 index.html、sw.js、manifest.webmanifest、icons/
  ├── scripts/build.mjs   建置到 dist/，並在 sw.js 寫入版本號、顯示用版本標籤與預先快取清單
  ├── scripts/serve.mjs   本機伺服器（開發模式不提供 sw.js）
  ├── tests/              node:test 單元測試
  ├── package.json
  ├── README.md
  └── <遊戲規格>.md
  ```

- 目錄名稱（以下稱 `<目錄>`）使用小寫英文字母，即部署網址的路徑（`/<目錄>/`）、localStorage 鍵的前綴與快取名稱的前綴，一經發布不得更改（更改會讓玩家的存檔與統計失聯）。
- 不限定前端框架，但建置產物須為純靜態檔案；建議沿用現有遊戲的做法：不使用任何 npm 套件，只用 Node.js 內建模組（Node.js 16.17 以上）。
- 所有資源以**相對路徑**引用，讓遊戲放在任意子目錄都能運作；不得引用網站根目錄的絕對路徑（`/` 開頭）。
- 遊戲核心流程不得依賴外部 CDN、API 或遠端字型。
- `package.json` 提供下列指令（名稱一致，方便大廳統一呼叫）：

  | 指令 | 用途 |
  | --- | --- |
  | `npm run dev` | 開發模式，提供 `src/`，不啟用 Service Worker |
  | `npm run build` | 建置到 `dist/` |
  | `npm run preview` | 建置並以 `dist/` 啟動，啟用 Service Worker |
  | `npm test` | 單元測試 |
  | `npm run check:puzzles` | 有出題器的遊戲：各難度批次出題驗收 |
  | `npm run icons` | 重新產生圖示 |

- 遊戲規則與出題、解題等純邏輯須與畫面分離，並有自動化單元測試。
- 每個函式前須有說明用途的繁體中文註解；公開或較複雜的函式使用 JSDoc。

## 大廳整合介面

### 目錄與註冊

- 網站結構：大廳在網站根目錄，每個遊戲的 `dist/` 放在根目錄下的 `<目錄>/`。
- 遊戲完成後須依「上架到大廳」一節加入大廳；開發中的遊戲不加入大廳。

### 本機儲存鍵

- 遊戲寫入的所有 localStorage 鍵都以 `<目錄>.` 開頭（例如 `sudoku.save`）；不得寫入其他前綴的鍵，唯一例外是讀取 `games.portal`（見下方）。
- 大廳以**唯讀**方式讀取下列兩個鍵，格式須維持相容；欄位可以增加，但不得刪除或改變意義：

  | 鍵 | 大廳使用的欄位 |
  | --- | --- |
  | `<目錄>.save` | `difficulty`（難度代碼）、`elapsedMs`（已累計遊玩毫秒數）、`completed`（布林值，完成後存檔即刪除，通常不會是 true） |
  | `<目錄>.stats` | 以難度代碼為鍵的物件，每個難度含 `started`、`completed`、`bestMs`（無紀錄時為 `null`）、`totalMs`、`noHint` |

- 難度代碼固定為 `easy`、`medium`、`hard`、`expert`，顯示名稱為「簡單」「中等」「困難」「專家」。遊戲沒有四級難度時，只使用其中幾個代碼；需要新的難度代碼時，須先更新大廳的 `DIFFICULTY_LABEL`。

### 返回大廳

- 大廳會在 localStorage 的 `games.portal` 記錄自己的路徑。遊戲首頁讀取此值：值以單一 `/` 開頭（不可為 `//` 開頭）時，顯示「‹ 所有遊戲」連結指向該路徑；沒有值或格式不符時不顯示。

### Service Worker

- Service Worker 位於遊戲目錄的 `sw.js`，以 `./sw.js` 註冊，scope 為遊戲目錄本身。
- 快取名稱使用 `<目錄>-<版本>` 格式；啟用新版時只刪除 `<目錄>-` 開頭的舊快取，不得刪除大廳（`portal-`）或其他遊戲的快取。
- 只處理自己 scope 內的同源 GET 請求；不呼叫會影響其他 scope 的 API。
- 支援 `CHECK_CACHE` 訊息：以 `MessageChannel` 回覆 `{ ok, missing, version, label }`，`ok` 表示所有必要資源都已在快取中，`missing` 為缺少的檔案數，`version` 為內容雜湊（快取名稱用），`label` 為顯示用版本標籤。大廳以此判斷「離線可玩」並顯示版本。
- 版本標籤格式為「最後修改 `src/` 的 commit 日期・內容雜湊前 7 碼」（例如 `2026.10.25・c27e2a1`），由 `scripts/build.mjs` 產生並寫入 `sw.js` 的 `LABEL`；遊戲首頁的離線狀態旁顯示此版本。只改文件（`src/` 以外）不得產生新版本。
- 支援 `SKIP_WAITING` 訊息：由頁面在玩家同意更新時送出，啟用等待中的新版。
- 大廳可能在玩家從未開啟遊戲時，就直接註冊 `<目錄>/sw.js` 預先下載；`install` 階段須能獨立完成全部資源的快取，不得依賴頁面先開啟過。
- 判斷自己的離線狀態與新版本時，一律詢問**自己註冊的** Service Worker（`registration.active`／`registration.waiting`），不得使用 `navigator.serviceWorker.controller`：首次開啟時頁面可能暫時由大廳的 Service Worker 控制。

## 遊戲流程

1. 首頁提供：依難度開始新局、有未完成的局時「繼續遊戲」（顯示難度、耗時等摘要）、離線就緒狀態、統計、玩法說明，以及（符合條件時）「‹ 所有遊戲」連結。
2. 同時只保存一局。開始任何難度的新局會覆蓋目前進度；若已操作過，須先確認。
3. 「重開本局」保留同一題目，所有玩家操作、耗時、錯誤次數與提示額度回到新局狀態；若已操作過，須先確認。
4. 完成時停止計時並鎖定盤面，顯示完成畫面：難度、耗時、錯誤次數、已用提示次數；創下該難度最佳時間時一併標示，並提供「再玩一局」與「回首頁」。完成後清除存檔。
5. 答錯不結束遊戲，不設錯誤次數上限（遊戲規格另有規定除外）。
6. 遊戲中按瀏覽器或系統的返回操作時，不得直接離開頁面或遺失進度：先回到首頁（進度已保存），在首頁再返回才離開。
7. 「開始新局」「重開本局」「重設統計」等會清除資料的操作一律須確認。

## 操作與回饋

- 常用操作（輸入、筆記、清除、復原、提示、暫停）集中在畫面下方，手機直向時拇指可及；盤面位於其上方。
- 觸控按鈕至少 44 × 44 CSS px。盤面格子在 375 CSS px 寬的直向畫面上，須在不縮放的情況下能準確點選（下限由遊戲規格訂定）。
- 錯誤除了顏色也須有文字或圖示說明（例如紅字加 ✕），避免只靠顏色辨識。
- 無法執行的操作（例如修改題目給定的內容、提示用完）不得靜默失敗，須以短訊息說明原因。
- 有提示功能時：額度屬於每一局，依難度設定，新局或重開本局時重設；只有成功提示才扣次數；提示填入的內容有可辨識標記且之後鎖定；用完後停用並說明，不要求連網或付費；提示不能被復原，成功提示後清空先前的復原紀錄。
- 有復原功能時：依序撤銷玩家操作，不扣回已累計的錯誤次數；復原紀錄不需在重新整理後保留。
- 桌面鍵盤：
  - 方向鍵移動選取。
  - 共用快捷鍵：N 切換筆記、H 提示、P 或 Esc 暫停、Ctrl／⌘＋Z 復原；暫停時按 Enter 或空白鍵繼續。遊戲沒有對應功能時忽略該鍵。
  - 其他輸入鍵由遊戲規格定義，不得與共用快捷鍵衝突。

## 交通工具上的操作

- 防誤觸：
  - 停用雙擊放大與捏合縮放。
  - 停用 Android 下拉重新整理（overscroll）。
  - 停用長按選取文字、長按系統選單與點擊高亮閃爍。
  - 不以拖曳作為必要的操作方式，避免車上晃動造成誤放。
  - 會清除進度的操作不放在常用輸入按鈕旁邊。
- 省電：
  - 不使用持續播放的動畫；介面轉場與回饋效果以短暫、單次為限，並尊重「減少動態效果」設定。
  - 不要求螢幕常亮（不使用 Wake Lock）。
  - 出題與預先產生完成後，不在背景持續運算或計時輪詢；暫停或頁面在背景時停止所有計時器。
- 主題：預設跟隨系統的淺色／深色設定，並提供手動切換（跟隨系統／淺色／深色），手動選擇保存在本機。

## 暫停與計時

- 提供暫停按鈕。暫停時停止計時並遮住盤面及所有可能透露盤面資訊的內容，只顯示「繼續」。
- 頁面切換到背景時自動暫停並存檔；回到頁面時維持暫停畫面，由玩家按「繼續」恢復。
- 耗時以「累計經過時間」計算：以單調遞增的時鐘（例如 `performance.now()`）累加每段進行時間，暫停或進入背景時把該段加入累計值並存檔。
- 不得以「開始時刻與目前時刻的差」計算耗時。裝置時區變更、系統自動校時或手動改時間，都不得讓耗時跳動、變成負數或異常增加。
- 耗時格式為 `mm:ss`，超過 1 小時為 `h:mm:ss`，遊戲中持續顯示。

## 出題（有出題器的遊戲）

- 題目在裝置本機隨機產生，必須能在離線環境運作。
- 題目必須只有一組解答，且以遊戲規格定義的邏輯技巧即可解出，不得需要猜測或試錯；產生後須以完整回溯解題器驗證唯一解（找到第 2 組即判定失敗）。
- 難度以「僅會指定技巧的邏輯解題器」判定，以解完所需的最高技巧等級決定；其他盤面數量指標只作輔助篩選。
- 出題在 Web Worker 中執行，出題期間主畫面不得卡住並顯示載入狀態。Web Worker 無法建立或載入失敗時，改在主程式以已載入的出題器出題，不得因此無法開新局。
- 效能預設值（中階手機）：簡單與中等 2 秒內、困難 5 秒內、專家 10 秒內完成出題；簡單至困難超過 15 秒、專家超過 30 秒視為逾時，停止並顯示失敗訊息與重試按鈕，不開始無效題目。
- 預先產生：開始一局後於閒置時，在 Web Worker 為剛開始的難度預先產生下一題並存在本機（`<目錄>.pregen`），完成後即停止；使用後刪除，不存在或損毀時即時出題。
- 在本機保存最近 50 題的題目雜湊值（`<目錄>.recent`），新題目不得與其中任何一題完全相同。

## 統計

- 每個難度分別記錄：已開始局數、完成局數、最佳時間、平均完成時間（由 `totalMs ÷ completed` 計算）、未使用提示完成的局數；格式見「大廳整合介面」。
- 只有完成的局計入時間統計；重開本局不算新的一局。
- 統計只存在本機，提供「重設統計」並須確認。統計資料損毀時重設為空白，不影響遊戲進行。

## 本機儲存

- 自動儲存繼續遊戲所需的全部資料（題目、解答、難度、玩家操作、筆記、提示紀錄、錯誤次數、已累計遊玩時間）；資料只儲存在使用者裝置。
- 每次改變盤面或進度的操作，以及暫停、進入背景時立即存檔；不得只依賴關閉頁面時觸發的事件（iOS 可能在背景直接結束頁面而不觸發）。
- 存檔含格式版本號（`v`）。讀取時若版本無法辨識或資料不完整、彼此矛盾，依「資料損毀」處理：顯示提示並允許開始新局，不讓畫面卡在無法操作的狀態。
- localStorage 無法使用（例如私密瀏覽）時仍可遊玩，並在首頁提示關閉後進度會遺失。
- 所有讀寫都須容錯，任何儲存錯誤不得讓遊戲停止運作。
- 已知限制（須在首頁或說明中告知）：
  - iOS Safari 對未加入主畫面的網站，可能在 7 天未使用後清除本機資料。
  - iOS 每個主畫面圖示的資料各自獨立，也和 Safari 不相通。只把大廳加到主畫面，或只把各遊戲分別加到主畫面，兩者不要混用。
  - 於 iOS 瀏覽器（非主畫面 App）中開啟時，首頁應提示「加入主畫面」並說明上述限制。

## PWA 與離線

- 提供 PWA manifest（`start_url` 與 `scope` 為 `./`）與圖示（192、512、maskable 512、apple-touch-icon、SVG），以 Service Worker 快取執行遊戲所需的全部資源（HTML、JS、Web Worker 腳本、CSS、圖示、manifest）。
- 快取策略：遊戲資源一律「快取優先」，不得等待網路回應才顯示畫面；導覽請求回傳快取的 `index.html`。網路緩慢、需要登入的公共 Wi-Fi（Captive Portal）或請求被導向其他網頁時，仍須立即以快取開啟。
- 離線就緒狀態：首頁顯示「✓ 已可離線使用」或「離線資源下載中」；須在自己的 Service Worker 已啟用且所有必要資源都確認在快取中（`CHECK_CACHE`）後，才顯示「已可離線使用」。
- 版本更新：新版 Service Worker 須完整快取新版所有資源後才可啟用，之前不得刪除舊版快取。下載完成後顯示「有新版本，重新整理以更新」，由玩家決定何時更新，不得在遊戲進行中強制重新載入。更新後須能讀取舊版存檔與統計，或依「資料損毀」處理。
- 回到前景時可在背景檢查新版本（建議最多每小時一次），失敗不影響遊戲。
- 開發模式不啟用 Service Worker 快取，避免載入舊程式碼；驗證離線功能時才以建置結果啟用。
- 「出發前檢查」說明統一放在遊戲大廳（Android Chrome／三星瀏覽器、iPhone Safari 的安裝步驟，以及飛航模式離線測試），遊戲內不另外提供。

## 相容性與無障礙

- 目標裝置：作者本人的手機（iOS Safari／主畫面 App 或 Android Chrome 的最新版本）及桌面瀏覽器（Chrome 或 Safari 最新版本）。其他瀏覽器不保證支援。
- 版面以手機直向為主；手機橫向與平板須可正常遊玩（盤面與操作區可改為左右排列），不得出現水平捲動或操作被遮住。
- 版面須避開瀏海與 Home 指示條（使用 `env(safe-area-inset-*)`）。
- 建議（不列入驗收）：文字與錯誤標示的對比度符合 WCAG 2.1 AA；盤面格子與按鈕提供螢幕閱讀器標籤。

## 部署與 HTTPS

- 正式環境為 GitHub Pages：推送到 `game-portal-fly` repo 的 `main` 後，根目錄的 `.github/workflows/pages.yml` 執行 `npm test`、以 `scripts/assemble.mjs` 組合大廳與所有遊戲為 `site/`，並部署到 GitHub Pages。
  - 網址：大廳 `https://matishsiao.github.io/game-portal-fly/`，各遊戲 `https://matishsiao.github.io/game-portal-fly/<目錄>/`。
  - repo 須為公開，免費方案即可使用 GitHub Actions 與 GitHub Pages；repo 的 **Settings → Pages** 的 Source 設為 **GitHub Actions**。
  - 部署一律由根目錄的 workflow 執行，各遊戲目錄不另設 `.github` workflow。
- HTTPS 憑證由 GitHub 自動提供與續期；正式環境不得使用開發用自簽憑證。
- 建置產物為純靜態檔案，不需要後端。
- 選用的區網 HTTPS 開發模式以 mkcert 產生本機 CA 簽發的憑證；憑證私鑰與本機 CA 私鑰不得提交至版本控制。

## 共用驗收條件

各遊戲規格的驗收條件須包含遊戲特有的項目，並通過以下共用項目：

1. `npm test` 全部通過；有出題器的遊戲 `npm run check:puzzles` 各難度 100 題全部合格且符合效能目標。
2. 重新整理、關閉後再開啟，或在背景被系統結束後再開啟，進度與最後一次操作一致；完成時顯示結算畫面且存檔被清除。
3. 暫停或切到背景時計時停止且盤面被遮住；繼續後接續計時。遊戲中變更裝置時區或系統時間，耗時不跳動。
4. 完成一局後，該難度的統計正確更新，破紀錄時完成畫面有標示；大廳顯示的完成局數、最佳紀錄、「繼續遊戲」卡片與遊戲內一致。
5. 手機直向與橫向可單手完成所有主要操作，主要操作不被遮住，無水平捲動；雙擊、捏合、下拉、長按不會造成縮放、重新整理或跳出選單；遊戲中按返回不會遺失進度；桌面可用鍵盤遊玩。
6. 從大廳進入時首頁顯示「‹ 所有遊戲」且能返回大廳；單獨開啟遊戲網址時不顯示。
7. 只開啟大廳（從未開啟遊戲）並等待自動下載完成後，大廳顯示該遊戲「離線可玩」；之後離線直接開啟遊戲網址可正常遊玩。
8. 出發前檢查：在主畫面 App 中確認「已可離線使用」後，開啟飛航模式並重新開機，再開啟：可繼續原局、每種難度都能開始新局，中途切到背景再回來一切正常。
9. 未啟用 Service Worker 時，頁面已開啟的情況下斷網，仍可連續開始每種難度的新局。
10. 連上尚未登入的 Captive Portal Wi-Fi 或極慢網路時，仍立即以快取開啟並可遊玩。
11. 部署新版後，進行中的遊戲不被強制中斷；新版資源未下載完成前斷網，仍以舊版正常運作；玩家同意更新後能讀回原進度與統計。更新某個遊戲不影響大廳與其他遊戲的快取與離線狀態。
12. 正式網站使用有效且受信任的 HTTPS 憑證，並由 GitHub Pages 自動續期。

## 上架到大廳（遊戲完成後）

遊戲開發期間只放在 `games/<目錄>/` 單獨開發與測試（`cd games/<目錄> && npm run dev`），**不加入大廳**，因此不會被組合進網站、也不會被部署。**遊戲完成後必須加入大廳才算上架**：大廳是唯一的發布入口，玩家只會從大廳看到並下載遊戲。

### 上架前提（遊戲完成的定義）

- 遊戲規格的驗收條件與本文件的「共用驗收條件」全部通過。
- 在遊戲目錄執行 `npm test` 全部通過；有出題器的遊戲 `npm run check:puzzles` 各難度 100 題全部合格且符合效能目標。
- 符合「大廳整合介面」：localStorage 鍵前綴、`.save`／`.stats` 格式與難度代碼、Service Worker（快取前綴、`CHECK_CACHE` 含 `label`、`SKIP_WAITING`、詢問自己的註冊）、版本標籤、「‹ 所有遊戲」連結。
- 外觀採用與大廳一致的豐富色調：選定一組遊戲主色（漸層的兩個顏色），首頁漸層橫幅、各難度漸層按鈕、遊戲頂部列、彩色工具列；做法參考現有遊戲 `src/css/style.css` 末尾的「豐富色調」段落。盤面上代表語意的顏色（錯誤、提示、選取）不得被主色取代。
- 遊戲首頁不提供「出發前檢查」，由大廳統一提供。

### 上架步驟

1. **大廳遊戲清單**：在 `src/portal.js` 的 `GAMES` 加一筆，順序即大廳卡片順序：
   - `dir`：遊戲目錄名稱。
   - `title`：遊戲名稱（例如「數獨」）。
   - `desc`：一句話介紹，手機直向下不超過一行半。
   - `tags`：2 個標籤，每個為 `[圖示名稱, 文字]`，圖示名稱須存在於 `src/index.html` 的內嵌圖示集（`<symbol id="i-名稱">`），需要新圖示時一併加入。
2. **組合清單**：在 `scripts/assemble.mjs` 的 `GAMES` 加上 `<目錄>: 'games/<目錄>'`。
3. **卡片圖示**：在 `scripts/make-icons.mjs` 加入 56 × 56 的 `<目錄>.svg`（圓角、以遊戲主色為底），執行 `npm run icons` 產生 `src/icons/<目錄>.svg`；遊戲自己的 `src/icons/icon.svg` 建議使用同一圖案。
4. **卡片主色**：在 `src/portal.css` 的淺色與深色 `:root` 各加入 `--<目錄>-1`、`--<目錄>-2`（與遊戲主色相同），並加入 `.game-card[data-theme="<目錄>"] { background: linear-gradient(135deg, var(--<目錄>-1), var(--<目錄>-2)); }`。
5. **根目錄指令**：在根目錄 `package.json` 的 `test`、`check:puzzles`（有出題器時）串上 `npm --prefix games/<目錄> …`，並加上 `dev:<目錄>`。
6. **難度代碼**：遊戲使用共用難度代碼以外的代碼時，先更新大廳 `src/portal.js` 的 `DIFFICULTY_LABEL`。
7. **文件**：根目錄 `README.md` 的遊玩網址表加上 `https://matishsiao.github.io/game-portal-fly/<目錄>/`，並更新專案結構與網站結構；本文件「參考資料」加上該遊戲規格。

### 上架驗證與發布

1. 在根目錄執行 `npm test`，所有遊戲全部通過。
2. 執行 `npm run preview`，在 `http://localhost:5180/` 確認：
   - 大廳出現新遊戲卡片，圖示、主色、名稱、介紹、標籤與版本號正確，手機直向無水平捲動。
   - 自動下載後顯示「離線可玩」，「離線就緒」計數包含新遊戲。
   - 玩一局後回大廳，「繼續遊戲」卡片與戰績正確；完成一局後完成局數與最佳紀錄正確。
   - 遊戲首頁顯示「‹ 所有遊戲」且能返回大廳。
   - 離線後大廳與新遊戲都能開啟並開始新局；各遊戲與大廳的快取各自獨立（共用驗收條件 4、6、7、11）。
3. commit 並推送到 `main`，GitHub Actions 部署完成後，以正式網址再確認一次大廳與新遊戲。
4. 已安裝大廳的玩家下次連網開啟大廳時會自動看到新遊戲並下載其離線資源，不需要重新安裝。

### 下架與改名

- 遊戲目錄名稱一經上架不得更改（會讓玩家的存檔、統計與離線快取失聯）。
- 下架時從 `src/portal.js`、`scripts/assemble.mjs` 的 `GAMES` 移除，並移除卡片圖示、卡片主色與根目錄指令；已下載過的玩家手機中仍會保留舊版快取，直到瀏覽器清除。
